# ADR-0003：采用确定性优先的分层意图路由

## Status

Accepted — 2026-08-10

## Context

用户后续可能继续研究，也可能只是确认、暂停、感谢或基于现有报告追问。如果每条消息都直接交给 LLM 或 Planner，会产生误触发工具、额外成本、重复任务和糟糕的对话体验。

意图识别需要利用当前 case、待确认问题和运行状态，但不应让普通网页内容或长期记忆直接控制路由。

## Decision

采用三层漏斗：

1. 规则层处理明确社交、控制、确认和显式研究表达；
2. 上下文层结合 case、运行状态、待确认问题和报告证据处理省略式追问；
3. 受限分类器只处理前两层仍无法判断的请求。

路由输出严格意图枚举和权限字段。只有 `RESEARCH_NEW`、`RESEARCH_FOLLOWUP` 可以进入 Planner；`REPORT_QA` 只能使用现有报告和证据。

受限分类器首版默认关闭。未来只有在离线评测证明它提高模糊请求召回，同时错误触发研究工具率仍接近 0 时才启用。即使启用，也必须无工具、无网络、无长期记忆写入、短超时、低 token 和严格 Schema；失败时默认澄清，不默认研究。

## Consequences

### Positive

- “好的，谢谢”可以智能回应而不调用研究工具；
- 路由速度、成本和误触发率可独立测量；
- 后续追问可以延续同一 case，而不是拼接成新问题。

### Negative

- 规则和上下文优先级需要持续维护；
- 确定性首版对少见表达的召回可能较低；
- 分类器启用需要单独评测与安全门槛。

### Neutral

- “90% / 8% / 2%”是观测目标，不是硬编码配额；
- Router 可以读短期上下文，但外部工具权限由 Policy Gate 再次检查。

## Alternatives Considered

- **所有消息直接交给 LLM**：灵活但成本高、不可控，容易误调用工具；
- **纯关键词规则**：简单但多轮追问解析能力不足；
- **直接把历史对话交给 Planner**：混淆路由和规划职责，也扩大注入面。
