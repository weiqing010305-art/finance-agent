## 主线 1：AI 财报分析助手（RAG）

**定位**：上传上市公司财报 PDF → 自动抽取利润/现金流/风险 → 支持提问并**引用原文页码** → 多年对比。
**对标**：FinGPT 应用层，但只做财报做到极致。
**简历词**：RAG / LLM 应用 / 文档智能。

### 1.1 功能清单

**MVP（先跑通，约 1–2 周）**
- F1 上传 PDF，解析出纯文本 + 页码
- F2 按页/段落切片，每块带 `page` 元数据
- F3 用 Embedding 把切片变成向量，存入向量库
- F4 用户提问 → 向量检索最相关片段（带页码）
- F5 大模型基于检索原文回答，结论标注 `[Pxx]`
- F6 `retrieve` 工具封装为 `@tool`，Agent 自己决定何时检索
- F7 Hook 强制约束：回答/保存必须带页码引用，否则拦截

**增强（拉开差距，约 2–4 周）**
- F8 重排（Rerank）：先粗捞 20 段再精挑 3 段，提升准确率
- F9 多模态读图：财报柱线图/表格用 VLM 提取数字，带页码
- F10 多年对比：存 2021/2022/2023 指标，跨会话对比趋势
- F11 结构化输出：答案返回 `{结论, 页码[], 置信度}` 的 JSON
- F12 低温度控制：财报用 0.1~0.3，数字不发散

**生产（可上线，约 2–3 周）**
- F13 Eval 测试集：自建 20–50 道带标准答案+页码的题，规则断言打分（引用完整率 / 数字准确率）
- F14 网页界面：上传 PDF + 问答（Streamlit/Gradio）
- F15 服务化：FastAPI 挂成 API
- F16 追踪：记录每步调了啥工具，方便查 bug
- F17 成本路由：检索走小模型、总结走大模型

### 1.2 技术栈明细

| 环节 | 工具 | 用途 | 免费 | 难度 |
|------|------|------|------|------|
| PDF 解析 | **PyMuPDF(fitz)** / **pdfplumber** | 提取文字+页码，pdfplumber 更准 | 免费 | 低 |
| 切片 | 自写函数（按页/段/标题切） | 每块带页码元数据 | — | 低 |
| Embedding | **sentence-transformers**(BAAI/bge-small-zh-v1.5) / OpenAI text-embedding | 文字变向量 | 本地免费 / 云端付费 | 中 |
| 向量库 | **Chroma**（入门首选）/ **pgvector** | 存向量、按相似度检索 | 免费 | 低 |
| 重排 | **BAAI/bge-reranker-v2-m3** | 精排提升准确率 | 免费 | 中 |
| 多模态 | **Qwen-VL / Claude** + 图表提取 | 读柱线图数字/趋势 | 本地/付费 | 高 |
| Agent | **Strands Agent** | 模型驱动循环 | 开源 | 中 |
| 护栏 | **Hook**(BeforeToolCallEvent) | 没页码就拦下 | — | 低 |
| 界面 | **Streamlit / Gradio** | 上传+问答 | 免费 | 低 |
| 服务 | **FastAPI** | API 化 | 免费 | 中 |

## 主线 2：股票分析平台（数据 + 工程化）

**定位**：akshare 行情 + 技术指标(MACD/RSI/均线) + 回测 + Streamlit 交互看板。
**对标**：OpenBB 极简版，聚焦 A 股 + 中文财报。
**简历词**：API / 数据分析 / 可视化 / 工程化。
**关键判断**：这条线**不用 Strands**，纯数据工程；只有「自然语言问数据」可选层才用。

### 2.1 功能清单

**数据层（约 1 周）**
- F1 拉取 A 股实时/历史行情（akshare）
- F2 拉取财务数据、基础信息
- F3 定时缓存到本地库（SQLite/PostgreSQL），减少重复请求

**分析引擎（约 1 周）**
- F4 计算技术指标：MACD / RSI / KDJ / 均线 / 布林带
- F5 策略信号标记（金叉/死叉、超买超卖，用于看板高亮）

**看板（约 1 周）**
- F6 交互 K 线 + 指标叠加图（Plotly）
- F7 自选股监控面板
- F8 信号/预警汇总面板
- F9（可选）自然语言问数据：把行情函数挂成 `@tool`，Strands 听懂人话挑函数

### 2.2 技术栈明细

| 环节 | 工具 | 用途 | 免费 | 难度 |
|------|------|------|------|------|
| 行情/财务 | **akshare**（免费）/ **tushare**（更全，需积分） | 拉数据 | 免费/积分 | 低 |
| 存储缓存 | **SQLite / PostgreSQL** | 定时缓存 | 免费 | 低 |
| 指标计算 | **pandas + numpy + TA-Lib** | MACD/RSI/KDJ/均线 | 免费 | 中 |
| 看板 | **Streamlit** | 交互界面 | 免费 | 低 |
| 图表 | **Plotly** | 交互 K 线/指标图 | 免费 | 低 |
| 可选 AI | Strands + 行情函数 | 自然语言问数据 | 开源 | 中 |

### 2.3 目录结构（建议）

```
mainline2_platform/

│   ├── fetch_data.py     # F1-F3 数据
│   ├── indicators.py     # F4 技术指标
│   ├── signals.py        # F5 信号
│   ├── db_cache.py       # F3 缓存
│   ├── charts.py         # F6-F8 图表/看板
```

### 2.4 里程碑 & 验收标准

| 里程碑 | 完成标志 | 验收 |
|--------|----------|------|
| M1 数据 | F1–F3 | 输入股票代码返回历史行情 DataFrame |
| M2 引擎 | F4–F5 | 算出 MACD/RSI；图表标记金叉/死叉/超买超卖 |
| M3 看板 | F6–F9 | 网页打开看 K 线+指标；信号/预警面板可用 |

## 主线 3：股票研究 Agent（多 Agent 编排）

**定位**：一句话「分析腾讯」→ 自动跑股价/新闻/财报/评级 → 汇总报告。
**对标**：AI Hedge Fund / TradingAgents。
**简历词**：Agent / 工具调用 / 多步推理。
**复用**：主线 1 的 `retrieve` 工具 + 主线 2 的行情/指标函数。

### 3.1 功能清单

**编排骨架（约 1 周，依赖前两条线）**
- F1 总管 Agent 收「分析腾讯」，自己决定调用顺序（Strands agents-as-tools）
- F2 多步推理 + 反思（DeepSearch 循环：不够就换问法再查）
- F3 收集各专家结果，生成结构化研究报告

**专家工具（复用前两线，约 1 周）**
- F4 股价工具 = 主线 2 的 akshare 行情函数（包成 `@tool`）
- F5 财报工具 = 主线 1 的 `retrieve(pdf, query) -> {text, page}`
- F6 新闻工具 = akshare 财经新闻 / 东方财富快讯
- F7 评级工具 = akshare 机构评级

**产出与合规（约 1 周）**
- F8 输出 Markdown / JSON 报告（可解析、可追溯）
- F9 Handoff：关键结论（如「建议买入」）转人工审核
- F10 追踪 + Eval：查多 Agent 调顺序、测漏查

### 3.2 技术栈明细

| 环节 | 工具 | 用途 | 免费 | 难度 |
|------|------|------|------|------|
| 框架 | **Strands agents-as-tools** | 总管调专家 | 开源 | 中 |
| 模型 | 同主线 1 | — | — | — |
| 股价工具 | 主线 2 的 akshare 函数 | 复用 | 免费 | — |
| 财报工具 | 主线 1 的 retrieve | 复用 | — | — |
| 新闻/评级 | **akshare** | 财经新闻/机构评级 | 免费 | 低 |
| 输出 | Markdown / JSON | 报告 | — | 低 |
| 合规 | **Strands Handoffs** | 转人工 | 开源 | 中 |
| 追踪/评估 | Strands tracing + Eval | 查顺序/测漏查 | — | 中 |

### 3.4 里程碑 & 验收标准

| 里程碑 | 完成标志 | 验收 |
|--------|----------|------|
| M1 骨架 | F1–F3 | 说「分析腾讯」，Agent 自动跑完并出报告 |

## 共享底座与复用关系（三条线不是孤岛）

- 主线 1 的 `retrieve` 工具 = 主线 3 的「财报专家」
- 主线 2 的 行情/指标函数 = 主线 3 的「股价专家」+ 主线 2 看板本体
- 三者共享 模型层 + Strands

---

## 推进顺序（推荐）

1. **主线 1 MVP** —— 先跑通 RAG 底座，切片/Embedding/向量库/Hook 全部落地
2. **主线 2 数据层 + 指标** —— 锻炼纯工程能力，产出可复用函数
3. **主线 3 编排** —— 把前两条线的函数挂成 tool，Strands 一把串起来
4. 回头给主线 1 加 **重排 / 多模态 / Eval**
5. 主线 2 完善看板（信号/预警面板）
