# FinScope 基线评测设计

## 目标

在重构研究 Agent 前，先为当前系统建立可重复的质量基线。评测直接调用现有
FastAPI 接口，不复制业务逻辑，也不默认发起付费请求。运行者必须显式启动所需
的 mock 或 DeepSeek 服务，再执行评测命令。

第一版使用 10 个固定案例，覆盖 A 股、港股、证券身份歧义、证据不足和来源冲突。
案例保存预期公司、证券代码、市场以及需要人工检查的行为。自动评分只计算能够
从当前 API 响应确定验证的指标：任务完成、公司身份匹配、报告结构、引用完整性、
URL 格式、首次结果时间和总耗时。引用是否真正支持结论、token 和费用在当前接口
没有可靠数据时必须输出 `null`，不得用启发式分数冒充真实结果。

## 组件与数据流

`evals/cases.jsonl` 是版本化案例集；`evals/run_eval.py` 创建研究任务并轮询到终态；
`evals/graders.py` 对单条任务响应评分并聚合结果；最终 JSON 报告写入
`evals/reports/`。每个案例保留原始终态响应和错误摘要，便于回放失败。

运行器设置任务级超时，并支持 `--limit` 做低成本冒烟。URL 网络可访问性检查默认
关闭，只有显式传入 `--check-urls` 才访问证据链接。运行器不读取或打印 API Key。

## 完成标准

- 10 个案例能够被严格校验并加载。
- mock 模式可完成至少一条端到端评测并生成报告。
- 错误、超时和无法连接 API 时仍生成可诊断结果。
- 自动指标名称清楚区分“引用完整性”和“引用语义支持率”。
- 项目原有测试与新增评测测试全部通过。
